# Search Simulator 算法设计

> 本文只描述研究目标、博弈假设、状态与信息、分支语义、数学定义、复杂度和设计不变量。
> 文件级实现、接口、依赖、迁移和验证记录统一写入 `CODE_DESIGN.md`。

## 1. 研究目标

本模块用于研究狼人杀中的零和阵营博弈。博弈参与方抽象为：

- 好人阵营：最大化好人最终胜利效用；
- 狼人阵营：最小化好人最终胜利效用。

算法对角色站位、昼夜行动、白天投票和显式战术形成的状态图进行迭代，研究理性过滤后仍然成立的全部分支，而不是随机游走。

当前阶段的目标是构建“最优算法研究框架”。智能投票属于功利理性启发式剪枝，不宣称已经求得 minimax、PBE 或其他全局均衡解。

## 2. 搜索边界

### 2.1 DFS 与 BFS

GUI 只提供 DFS。DFS 优先展开最新生成的节点，适合控制大规模分支搜索的前沿内存。

BFS 只通过 CLI 显式启动，用于按深度观察状态分布。两种模式必须共享相同的状态转移规则；访问顺序之外的差异都属于错误。

### 2.2 智能模式

智能投票默认开启。关闭后执行未经过功利理性过滤的合法分支基线，全部战术同时禁用。

智能模式的约束优先级为：

```text
游戏硬规则
> 用户勾选的战术约束
> 阵营理性目标
> 个人身份启发式
> 同级目标分支展开
```

reward interval 不参与上述优先级，也不参与搜索决策。

## 3. 信息模型

### 3.1 游戏视角

算法中的每个行动者只能使用自己在真实对局中能够获得的信息：

- 玩家知道自己的真实身份；
- 狼人知道其他狼人；
- 预言家知道自己的私有查验结果；
- 公开发言、公开声明和公开查验进入公共历史；
- 未公开的真实身份不能用于投票、保护或攻击目标过滤。

### 3.2 死亡身份

死亡不会自动公开身份。唯一例外是愚者因白天放逐触发“身份揭示”。

死亡只是不新增身份信息，不会删除既有公共知识。例如某玩家生前已被公开查验为狼人，该信息在其死亡后仍然保留。

### 3.3 上帝视角

可视化 UI 使用研究者上帝视角，可以显示真实身份，但必须区分：

- 仅研究者知道的真实身份；
- 玩家公开声明的身份；
- 已被公共信息确认的阵营；
- 仅预言家本人知道的私有查验。

UI 展示的信息不能反向进入算法的游戏视角。

## 4. 角色站位

默认七人板子保持：

- 2 名狼人；
- 1 名预言家；
- 1 名女巫；
- 1 名守卫；
- 2 名村民。

唯一站位数为：

```latex
\frac{7!}{2!\,2!}=1260
```

愚者默认不勾选。启用愚者时，愚者占用一个原本属于村民的席位；默认七人板子相应变为 1 名村民和 1 名愚者。

不同站位属于不同的隐藏身份世界，不能仅凭公开状态相似跨站位合并。

## 5. 愚者规则

愚者属于好人阵营和神职，拥有一次被动技能“身份揭示”。

当愚者在白天成为放逐目标时：

1. 愚者公开真实身份；
2. 本次放逐不造成死亡；
3. 当天立即结束，不进行第二轮投票；
4. 愚者保持存活并继续计入神职存活条件；
5. 愚者永久失去投票权；
6. 后续白天投票统计不再包含愚者的票。

智能模式下，所有玩家默认不再把已揭示愚者作为白天投票目标。

## 6. 状态与 DAG

一个可续算状态必须完整描述未来合法转移，包括：

- 真实站位和存活状态；
- 当前昼夜阶段与轮次；
- 角色资源和历史限制；
- 愚者是否已经揭示；
- 私有查验、公共查验和公共身份声明；
- 次夜战术目标；
- 影响未来行动集合的其他公共历史。

只允许合并未来转移完全等价的状态。若两个状态的技能、信息、声明、愚者状态或未来合法目标不同，即使当前死亡名单或预测胜方相同，也不能合并。

状态节点可以拥有多个父节点。所有产生原因属于父子边，而不是子节点的单一 parent 字段。每条边必须保存完整原因和对应 multiplicity。

## 7. 智能投票

### 7.1 过滤顺序

对每名投票者，智能目标集合按以下顺序形成：

1. 应用游戏规则和战术硬约束；
2. 排除自己、已揭示且失去投票交互意义的愚者以及其他非法目标；
3. 排除该投票者已经确认的同阵营目标；
4. 优先保留该投票者已经确认的敌对阵营目标；
5. 没有确认目标时，使用个人身份启发式；
6. 同优先级目标全部保留并分别展开。

### 7.2 阵营与个人信息

- 狼人知道狼队成员，因此默认不投票狼人同伴；
- 预言家优先投票自己私下查验到的狼人；
- 预言家公开查验后，其他好人才可以使用该查验；
- 其他好人排除公开确认的好人，在剩余未知目标中展开；
- 已揭示愚者不产生自己的投票，也不成为智能投票目标。

“明显狼人”只是提示性说法，不引入额外行为识别算法。本阶段可确认狼人主要来自预言家查验；私有查验只对预言家本人有效，公开查验才进入公共信息。

### 7.3 同级目标

智能模式不是固定座位 tie-break。同级目标均形成独立分支，分别讨论后续迭代结果。这样可以避免人为制造座位偏差。

## 8. 狼人夜间目标

智能模式下，狼人攻击优先级为：

```text
战术指定目标
> 公开身份或公开声明的女巫
> 公开身份或公开声明的守卫
> 公开身份或公开声明的预言家
> 已揭示愚者
> 其他已确认好人
> 其他未知非狼目标
```

狼人无法区分真实预言家和挡刀村民的神职声明，因此公开声明者同样进入优先目标。同一级目标全部展开。

当多个目标的转移结果完全等价时，可以合并后继状态，但每个刀口原因仍保留在边上。

守卫、女巫和预言家的角色行动在本阶段仍完整展开，不纳入智能启发式剪枝。

## 9. 战术树

战术仅在智能投票开启时可见并生效。勾选战术表示在正常行动基线之外增加对应战术分支；战术分支内部的约束高于智能过滤。

### 9.1 白天战术

#### 村民挡刀

枚举存活村民的挡刀声明组合。村民可以声明预言家身份，但不能伪造具体查验结果。复数挡刀者分别成为可能的次夜指定目标。

#### 预言家不跳

预言家可以保持隐藏或公开身份及允许公开的真实查验。公开后进入狼人公开神职优先目标。

#### 狼人跟票

所有存活狼人把投票集中在同一合法非狼目标，并对同级目标分别展开。

### 9.2 黑夜战术

#### 狼人自刀骗解药

该战术只有在以下条件同时成立时才合法：

- 对局中存在女巫或守卫；
- 当前存活狼人数量不少于 2；
- UI 中已勾选该战术。

每名存活狼人分别成为可能的自刀目标。若没有被守护或使用解药，该狼人正常死亡。

#### 狼人空刀

该战术只有在对局中存在女巫或守卫时可勾选。空刀分支没有狼刀目标，但女巫毒药等独立行动仍正常结算。

## 10. 零和效用

统一使用好人视角终局效用：

```latex
u(z)=
\begin{cases}
+1, & z\text{ 为好人阵营胜利},\\
-1, & z\text{ 为狼人阵营胜利}.
\end{cases}
```

智能规则首先根据阵营关系约束目标；当阵营信息不足时才使用个人身份启发式。当前 interval 不用于比较或选择行动。

## 11. Wide/Narrow Reward Interval

### 11.1 设计定位

移除 Wilson 统计置信区间。wide/narrow interval 是对状态子结构的 Robust 观测量，不是置信区间，也不是分支概率估计。

设计假设为：

```latex
I_{\mathrm{narrow}}(v)
\subseteq
I_{\mathrm{true}}(v)
\subseteq
I_{\mathrm{wide}}(v)
```

该夹逼关系是研究模型公理，不声称具有统计覆盖率证明。

### 11.2 叶子值

```latex
I(v)=
\begin{cases}
[1,1], & v\text{ 为好人胜利终局},\\
[-1,-1], & v\text{ 为狼人胜利终局},\\
[-1,1], & v\text{ 为未决或无可计算后继节点}.
\end{cases}
```

### 11.3 回传范围

每个节点只读取去重后的直接子节点集合：

```latex
C(v)=\{c\mid (v,c)\text{ 是一条父子关系}\}
```

回传不读取：

- 父节点关系；
- 同一父子状态之间的多条派生原因；
- 边 multiplicity；
- 终局路径总数。

### 11.4 子节点均值

设每个直接子节点同时具有区间 `[L_i,U_i]`，子节点数量为 `n`：

```latex
\overline L=\frac{1}{n}\sum_{i=1}^{n}L_i
```

```latex
\overline U=\frac{1}{n}\sum_{i=1}^{n}U_i
```

### 11.5 Wide interval

```latex
L_{\mathrm{wide}}
=
\lambda\min_i L_i+(1-\lambda)\overline L
```

```latex
U_{\mathrm{wide}}
=
\lambda\max_i U_i+(1-\lambda)\overline U
```

### 11.6 Narrow interval

先计算原始端点：

```latex
A
=
\lambda\max_i L_i+(1-\lambda)\overline L
```

```latex
B
=
\lambda\min_i U_i+(1-\lambda)\overline U
```

若端点倒置，始终交换边界，不提供反转开关：

```latex
L_{\mathrm{narrow}}=\min(A,B)
```

```latex
U_{\mathrm{narrow}}=\max(A,B)
```

### 11.7 风险参数

```latex
\lambda\in[0,1],\qquad \lambda_{\mathrm{default}}=0.5
```

λ 只控制 interval 的宽窄观测，不改变任何搜索分支。

### 11.8 计算时机

状态图构建完成后，按逆拓扑顺序同时计算 wide 和 narrow。状态图、终局效用和父子拓扑保持不变，因此用户在迭代完成后可以改变 λ，并对选中 DAG 动态重新回传 wide/narrow；该过程只更新观测值和颜色，不重新展开状态。

GUI 对选中站位实时重算；其他站位在被选中时按当前 λ 按需重算，避免滑块变化触发全部站位的重复读取。interval 绝不参与：

- DFS/BFS 前沿；
- 智能投票；
- 战术选择；
- 狼刀目标过滤；
- 状态签名；
- DAG 合并；
- LRU 淘汰。

### 11.9 分支颜色

颜色永远使用子节点的 wide interval。判定时先看区间是否整体位于零轴同侧：非负区间明确导向好人阵营，非正区间明确导向狼人阵营；只有跨零区间才比较两端绝对值：

```latex
\Delta=\left|\,|U_{\mathrm{wide}}|-|L_{\mathrm{wide}}|\,\right|
```

```latex
\mathrm{color}=
\begin{cases}
\mathrm{blue}, & L_{\mathrm{wide}}\ge 0\ \land\ U_{\mathrm{wide}}>0,\\
\mathrm{red}, & L_{\mathrm{wide}}<0\ \land\ U_{\mathrm{wide}}\le 0,\\
\mathrm{black}, & L_{\mathrm{wide}}\le 0\le U_{\mathrm{wide}}\ \land\ \Delta<0.001,\\
\mathrm{blue}, & L_{\mathrm{wide}}<0<U_{\mathrm{wide}}\ \land\ |U_{\mathrm{wide}}|>|L_{\mathrm{wide}}|,\\
\mathrm{red}, & L_{\mathrm{wide}}<0<U_{\mathrm{wide}}\ \land\ |U_{\mathrm{wide}}|<|L_{\mathrm{wide}}|.
\end{cases}
```

## 12. LRU 与持久化

LRU 只保存规范游戏迭代状态的签名映射，不保存 interval、UI 派生值或父节点关系。

持久化模型分别表达：

- 运行批次；
- 站位；
- 规范状态节点；
- 父子边；
- 每条边的完整派生原因；
- 原因 multiplicity；
- 搜索后计算的 wide/narrow interval。

SQLite 保持单写协调模型。全站位搜索按站位顺序串行推进：一个站位的完整分支 DAG 搜索、区间回传和持久化全部完成后，才进入下一个站位。站位之间不并发展开，避免多个组合爆炸图同时占用内存。

一个站位只有在摘要、全部节点和全部边均完成持久化且数量校验一致后，才形成检查点。运行批次保留规范配置与已完成站位集合；相同配置重新启动时复用最近的未完成批次，并跳过已经形成检查点的站位。因此进程异常、人工中断或内存保护中断只会使当前未完成站位重算，不会使已完成站位从头迭代。

搜索持续观察系统可用内存。可用内存进入安全保留区时，当前批次转为可恢复中断并停止派发后续站位。若中断发生在站位边界，直接从下一站位恢复；若发生在站位内部，该站位的临时结果不构成检查点，释放后从该站位根状态重算。这里不对未完成 DAG 做增量合并，因为缺少完整逆拓扑回传的局部图不能证明与最终转移完全等价。

为避免大分支节点在 interval 回传时产生与子节点数量成比例的临时对象，wide/narrow 的最值、累加和与子节点计数应单遍流式聚合。该聚合与原公式完全等价，不改变 lambda、narrow 反转或分支着色定义。

节点长期保留的状态表示使用无损紧凑快照；完整 GameState 只在 API 输出、实时预览批次或 hover 检视时按需重建。紧凑表示必须足以恢复全部 GameState 字段，且不得变成新的合并键或改变转移等价性。

## 13. 可视化设计

Pygame UI 默认中文，不提供语言切换按钮。底层 i18n 和 CLI 英文能力保留。

第一版包含：

- 参数与角色配置；
- 默认开启的智能投票；
- 仅智能模式显示的白天/黑夜可扩展战术树；
- 运行进度和缓存统计；
- 站位结果分页；
- 选中站位的 DAG 视图；
- 节点和边的缩放、平移及选择；
- 每条边的完整派生原因；
- 真实身份、公开声明和查验状态 icon；
- wide/narrow 数值同时展示，但边颜色只使用 wide。
- 迭代期间随已完成站位实时累计终局节点、好人路径、狼人路径和当前胜负关系；
- 迭代启动后立即显示当前站位，以及已展开节点、已发现节点、待展开节点和已生成边数；节点进度是搜索计数，不解释为完成概率；
- 站位进入搜索时立即出现在结果区，并从角色站位分布连续过渡到该站位的实时局部 DAG；运行中预览应持续呈现新节点和新边，而不是等待整个站位完成后才绘制；
- 搜索进度与局部 DAG 数据以 0.5 秒为刷新周期批量到达界面，交互帧率不受该周期限制；
- 每批新进入当前可见子树的节点以短时淡入呈现，已存在节点的状态更新不重复触发动画；
- 局部 DAG 初始只显示根节点或当前观测窗口的入口节点。点击节点展开其下一层子节点，再次点击该父节点时收起其子树；共享后代只有在所有未收起路径上都不可达时才隐藏；
- 提供针对当前有界观测图的“全部展开”和“全部收起”；前者只展开已进入观测窗口的节点，后者恢复为仅显示局部入口，二者都不改变搜索状态；
- 实时 DAG 是有界滚动观测窗口，只用于可视化当前展开过程，不改变完整 DAG、状态合并、路径计数或持久化结果；
- 持久化层只接收站位结果、完整节点快照和派生边，并通过类型化的数据访问接口读写；其实现方式不得反向影响搜索顺序、状态合并或 reward interval。
- GUI 启动的搜索必须与绘制进程隔离，包括只配置一个 worker 的情况；子进程异常不得直接破坏 Pygame 主循环。
- 允许暂停和恢复迭代；暂停保留现有 frontier、DAG 与计数，恢复后从同一搜索状态继续，不重新开始或丢弃分支；
- 节点本体只显示紧凑编号与阶段标记；hover 必须展示该节点的完整 GameState 快照，包括全部玩家生存/技能状态、日夜计数、公开信息、查验、投票、战术、站位签名与节点身份字段。完整数据使用面向研究者的中文 UI 标签、语义分组和逐行玩家信息呈现，不显示 JSON、字典字面量或机器字段引号；快照只用于观测，不参与状态签名、合并或 interval。

## 14. 复杂度与风险

主要组合增长来自：

- 全角色站位排列；
- 夜间行动笛卡尔积；
- 白天战术组合；
- 个体投票组合；
- 同级理性目标展开；
- 自刀目标、空刀和死亡连锁；
- 多个父分支汇入同一规范状态。

智能过滤减少明显不符合阵营利益的目标，但不保证状态空间变为多项式规模。

## 15. 设计不变量

- GUI 只运行 DFS，BFS 只能通过 CLI 显式启动；
- 智能投票默认开启，关闭后战术不可见且不生效；
- 战术优先于智能过滤；
- 算法决策只读取游戏视角信息；
- 死亡不自动公开身份，愚者揭示除外；
- 愚者揭示后存活、失去投票权且当天不重投；
- 同级目标全部展开；
- 只合并未来转移完全等价的状态；
- 每条边保留全部派生原因；
- LRU 只缓存游戏状态；
- Wilson 区间不存在；
- λ 默认值为 0.5；
- wide/narrow 只读取唯一直接子节点且忽略 multiplicity；
- narrow 始终规范化为上界不小于下界；
- interval 只作观测，不影响迭代；
- 迭代完成后调整 λ 只动态重算观测区间，不重新搜索；
- 分支颜色永远基于 wide interval。
