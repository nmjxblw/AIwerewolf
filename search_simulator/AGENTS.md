# AGENTS.md — search_simulator 模块约束

本文件仅约束 `search_simulator/` 子模块。该模块在设计、实现和文档上独立于父项目；处理本模块任务时，以本目录文件为准，父级项目文档不构成本模块算法设计的事实来源。

## 开工顺序

修改本模块前必须依次阅读：

1. `AGENTS.md`
2. `ALGORITHM_DESIGN.md`
3. `CODE_DESIGN.md`
4. `strategy_implemetation.md`

若用户提出新的设计要求，先更新对应文档并确认文档边界，再修改代码。

## 文档职责边界

- `ALGORITHM_DESIGN.md`：只记录算法模型、状态、分支、信息约束、区间定义和数学公式；不得记录文件名、类名、函数名、迁移步骤、依赖安装或测试命令。
- `CODE_DESIGN.md`：记录实现映射、代码改动、数据结构、持久化方案、迁移方案、依赖和验证结果。
- `strategy_implemetation.md`：记录战术实现难点、边界条件、失败模式和工程注意事项。
- 数学公式保留在 Markdown 文档中，并使用带 `latex` 语言标识的代码块包装。
- 本模块的文档修改只写入 `search_simulator/`，不得为了同步而修改父级文档。

## 算法不可变约束

### 搜索与界面

- 算法使用树分支迭代，不实现随机游走。
- GUI 固定使用 DFS，不显示运行模式；BFS 只能通过 CLI 显式启动。
- GUI 使用 Pygame / pygame_gui，默认中文，不提供语言切换按钮；底层 i18n 与 CLI 英文输出能力保留。
- GUI 标签不得重叠；原生控件与自绘战术项、表格行、DAG 节点和边都必须提供可见 hover 反馈，边 hover 可查看完整派生原因。
- GUI 参数输入框必须提供 hover 文本说明参数含义与合法范围。
- GUI 的 `lambda` 参数固定使用滑块与实时文本显示组合，范围 `[0,1]`，默认 `0.5`。
- GUI 所有角色、运行模式和战术勾选项必须提供 hover 文本；不可选战术仍需显示禁用原因。
- GUI 迭代时按已完成站位实时更新终局节点、好人路径、狼人路径和当前路径占优关系；不得把路径占比表述为概率。
- GUI 点击开始后必须立即进入可见运行状态，并在单个站位尚未完成时持续显示已展开节点、已发现节点、frontier、边数和当前站位；这些计数不得伪装为完成百分比。
- 站位进入 worker 后必须立即以“计算中”状态显示；DAG 面板必须在运行中接收增量节点和边，连续展示从站位分布到树展开的局部实时预览，不得等站位完成后才首次绘制。
- GUI 进度和 DAG 数据固定每 0.5 秒批量刷新；Pygame 交互循环必须保持正常帧率，不得将 hover、点击或暂停/恢复降为 0.5 秒轮询。
- 新进入可见子树的节点必须淡入，已存在节点更新不重复闪烁。DAG 初始只显示局部入口；点击节点展开其子节点，再点父节点收起其子树，布局和绘制只处理当前可见子图。
- DAG 必须提供当前有界观测图的“全部展开 / 全部收起”控件；该控件只能改变本地可见子图，不得触发搜索或修改 SQLite 图。
- 实时预览必须有界并明确属于观测窗口；为保持 UI 响应而丢弃旧预览节点不得影响完整搜索、SQLite DAG 或最终结果。
- GUI 必须提供暂停/恢复控件；暂停应保留 frontier、DAG 和已计算计数，并阻止 worker 展开下一节点，恢复后从原位置继续。
- DAG 节点保持紧凑显示，hover 时必须完整展示该节点 GameState 的所有字段及每名玩家的全部字段，不得仅显示摘要或固定前几行。完整快照只用于 UI/持久化观测，不得改变状态签名与 interval。
- 搜索节点不得为长期内存保留重复的完整嵌套 GameState 字典；必须保存无损紧凑快照，只在实时批次、API 输出或 hover 时按需重建完整 GameState。
- interval 回传必须使用单遍 count/sum/min/max 聚合，禁止为同一父节点构造与子节点数量成比例的 `RewardInterval`/`RobustIntervals` 临时列表。
- GUI 运行搜索时必须始终使用隔离子进程，即使 `parallel_workers=1` 也不得在 Pygame 主进程的普通后台线程中直接展开搜索；子进程异常必须转为 GUI 可见错误。
- 跨进程进度与完整结果传输必须使用有界队列和背压，不得把完整站位 DAG 作为无限积压的任务结果留在父进程；每个 worker 同时最多保留一个未完成站位任务，节点和边由单一 SQLite 写入者分批消费。
- GUI 是研究者上帝视角；算法决策必须严格使用对应玩家可见的信息。

### SQLite 访问

- 模块内所有 SQLite 建表、索引、查询、upsert、更新、删除、统计和 schema 检查必须使用 SQLAlchemy Core/Inspector API 构造；源码和测试中禁止明文 SQL、DDL、PRAGMA 及其字符串拼接。
- 持久化 API 必须封装连接与事务，不得向 GUI、搜索层或测试暴露 DBAPI cursor 作为常规读写通道。

### 智能投票与战术

- 默认开启智能投票。
- 仅在智能投票模式中显示、选择和执行战术；关闭智能投票时，战术集合必须为空。
- 决策优先级固定为：游戏硬规则 > 战术硬约束 > 阵营理性筛选 > 身份启发式 > 同级目标全部展开。
- 投票先考虑阵营目标，信息不足时才退化为个人身份启发式。
- 同级目标不得随机抽样或按座位号裁决，必须分别扩展分支。
- 智能模式是功利理性的启发式剪枝，不得宣称为已经证明的全局最优、极小极大均衡或完美贝叶斯均衡。

### 信息与身份

- 除愚者发动“身份揭示”外，所有死者身份不公开；死亡本身不得新增公开身份知识。
- 狼人知道狼队成员；预言家仅自己知道查验结果；其他好人只能使用公开信息。
- 上帝视角可展示真实身份、公开宣称、公开确认和预言家私有查验，但这些信息层级不得在算法中混用。
- 愚者属于好人阵营神职，默认板子不启用。其白天被投票出局时免死并公开身份，当天立即结束；此后永久失去投票权，也不再成为智能投票目标。

### 状态、DAG 与缓存

- 仅合并未来转移完全等价的状态。
- 父子边必须保留所有派生原因；相同父子节点的不同动作、目标或战术原因不得只压缩为一个代表动作。
- LRU 签名只包含规范化的游戏迭代状态；reward、interval、界面状态、边和派生原因都不得进入签名。
- 多路径计数和 multiplicity 可以独立保留，但不得影响 interval 向后传播。

## Reward interval 冻结规范

除非用户明确要求，不得擅自修改以下定义。任何与旧实现、旧文档或论文的冲突均以本节为准。

- 删除 Wilson 置信区间和 `confidence_level`。
- interval 是搜索完成后的观测量，不参与分支生成、智能投票、战术选择、目标排序、剪枝、状态签名、DAG 合并或 LRU。
- 搜索完成后允许用户动态调整 `lambda`，只对选中 DAG 重新回传 wide/narrow 并更新颜色，不得重新迭代；其他站位按选择惰性重算。
- 只使用 `wide_interval` 与 `narrow_interval`；不使用“乐观/保守”解释，不宣称统计置信度。
- 默认风险参数 `lambda = 0.5`，且 `lambda` 取值范围为 `[0, 1]`。
- 好人终局为 `[1, 1]`，狼人终局为 `[-1, -1]`，未决或没有可计算子节点的状态为 `[-1, 1]`。
- 每个节点只考虑其唯一的直接子节点集合；忽略父节点、多边合并关系、边 multiplicity 和多条派生原因。
- wide 使用子节点下界最小值、上界最大值与对应均值加权；narrow 使用子节点下界最大值、上界最小值与对应均值加权。
- narrow 始终执行既定的反转设计；计算后若下界大于上界，则交换边界，确保显示时上界不小于下界。不提供反转开关。
- 分支颜色永远依据子节点的 `wide_interval`：先判定符号，同为非负且不全为零时为蓝色，同为非正且不全为零时为红色；只有跨零时才比较上下界绝对值，差小于 `0.001` 为黑色，上界绝对值更大为蓝色，否则为红色；`[0,0]` 为黑色。

具体公式只以 `ALGORITHM_DESIGN.md` 为准。若用户明确改变 interval 设计，必须先修改算法文档和本文件，再改代码。

## 默认板子与战术

- 默认测试板子为 7 人：2 狼人、1 预言家、1 女巫、1 守卫、2 村民，共枚举 1260 种站位。
- 愚者默认不勾选；启用时替换一名村民。
- 白天战术：村民挡刀、预言家不跳、狼人跟票。
- 黑夜战术：狼人自刀骗解药、狼人空刀。
- 黑夜战术仅在女巫或守卫存在时允许选择；狼人自刀还要求运行时存活狼人数量至少为 2，并枚举每名存活狼作为自刀目标。
- 选中战术增加战术分支，正常基线分支仍然保留。
