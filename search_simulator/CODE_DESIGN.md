### 战术模型

白天战术：

- 村民挡刀；
- 预言家不跳；
- 狼人跟票。

黑夜战术：

- 狼人自刀骗解药；
- 狼人空刀。

战术树只在智能投票开启时生效。已勾选战术增加分支，正常行动基线保留。每个战术分支在目标过滤时具有最高优先级。

自刀分支要求存在女巫或守卫且存活狼人不少于两名。空刀要求存在女巫或守卫。无效战术不生成分支，UI 同步禁用不可用勾选项。

### 智能投票与狼刀

- 建立阵营识别辅助层，只允许读取行动者私有信息和公共信息；
- 投票先应用战术，再执行阵营过滤和个人启发式；
- 预言家使用私有查验，其他好人只使用公共查验；
- 狼人排除狼队成员；
- 同级目标全部展开，不使用固定座位 tie-break；
- 已揭示愚者不投票，也不成为智能投票目标；
- 狼刀优先公开神职声明者，依次为女巫、守卫、预言家、愚者；
- 守卫、女巫和预言家行动继续完整展开。

### 愚者结算

- 白天放逐愚者时不调用普通死亡链；
- 写入愚者揭示状态并消耗身份揭示技能；
- 当天直接进入夜间，不进行二次放逐；
- 愚者继续计入存活神职；
- 后续票型构造跳过其投票；
- 胜负条件将愚者计入神职集合。

- 删除 Wilson 与正态分布依赖；
- interval 数据改为同时保存 wide/narrow；
- 终局分别写入 `[1,1]` 和 `[-1,-1]`；
- 搜索完成后按逆拓扑序回传；
- 每个父节点对唯一直接子节点去重；
- interval 回传忽略边 multiplicity；
- narrow 倒置时自动交换端点；
- λ 默认 `0.5`；
- 边颜色只读取子节点 wide interval；
- interval 不进入智能投票、状态签名或 DAG 合并。

### DAG 与 LRU

- 规范状态键只描述未来转移所需的 GameState；
- 只合并未来转移完全等价的状态；
- 内存 LRU 保存状态签名到节点标识的热点映射；
- SQLite 签名记录只表示游戏状态；
- 父子边保存原因列表，而不是一个代表 action；
- 每个原因单独保存 action key、可读标签和 multiplicity；
- interval 与结果摘要保存在图节点/边结果中，不进入 LRU key。

### SQLite 持久化与 schema

- 所有建表、索引、查询、写入、upsert、更新、删除和计数统一使用 SQLAlchemy Core 的元数据与表达式 API；模块源码和测试中禁止出现明文 SQL/DDL/PRAGMA；
- SQLite 连接、事务提交、复合主键冲突处理和 LRU 磁盘清理均通过封装 API 执行，不向搜索层或 GUI 暴露 cursor 或 SQL 字符串；
- 启动时使用 Inspector API 校验已有表的必需列；不兼容的旧缓存明确报告需要重建，不用字符串拼接执行隐式迁移；

- 图节点增加 wide/narrow 四个边界列；
- 图边增加完整原因 JSON；
- 新建 schema 只包含 wide/narrow 边界和 reasons JSON，不再创建旧 reward 列或单 action 代替结构；
- 已有库由 Inspector 对必需列做非破坏校验；兼容 schema 直接使用，不兼容 schema 拒绝启动并要求保留/移走旧缓存后重建；
- 大整数路径计数继续使用 TEXT；
- worker 继续只计算，父进程保持 SQLite 单写；
- 计算 worker 的模块导入图不得包含 SQLite、SQLAlchemy 或 greenlet；持久化类只在父进程进入站位批处理协调器后惰性导入。IPC/SQLite 公用的批次上限放在纯 Python 配置层，避免 worker 为读取常量而加载数据库原生扩展；
- GUI 进度队列容量为 32，完整结果队列容量为 8；队列满时生产者等待消费者形成背压，不允许结果消息无界积压；
- 每个站位先发送小型摘要，再将节点和边分别按最多 64 条发送，最后发送完成标记；SQLite 写线程收到批次即通过持久化 API 提交，不再等待或复制整棵 DAG；64 条上限同时约束 IPC 消息、SQLAlchemy 参数装配和 SQLite 单次 executemany 的瞬时内存；
- 任务调度最多为每个 worker 保留一个 in-flight 站位，避免进程池待执行栈与站位数同步增长；GUI 即使单 worker 也走该结果队列；
- worker 每完成一个站位即退出并由进程池补充，释放 Python/原生分配器可能保留的大图内存；worker 崩溃或数据库写入失败时，未完成站位的部分节点、边和摘要由持久化 API 清理。

### Pygame GUI

- 删除 Tkinter 依赖；
- 使用 Pygame 主循环和 `pygame_gui` 控件；
- 所有标签按独立布局槽位排版，不允许页码、缓存、进度或状态文本共享基线发生重叠；
- 自绘复选框、战术分组、站位行、DAG 节点和分支边提供 hover 高亮，边和节点 hover 显示完整派生原因与状态详情；
- 每个参数输入框提供 hover 文本，说明参数语义、合法范围和界面限制；
- `lambda` 使用 `[0,1]` 滑块与实时数值文本组合，不接受自由文本输入；
- 搜索完成后滑块变化对当前选中 DAG 执行无权重逆拓扑回传，实时更新节点、边、根区间与颜色，不重新运行 DFS；未选中站位在选中时按当前值惰性重算；
- 每个站位结果回调实时累计终局节点、好人路径、狼人路径和当前路径占优关系，并在 DAG 顶部独立统计条显示；
- 搜索 worker 以 0.5 秒为硬节流周期上报站位编号、已展开节点、已发现节点、frontier、边数和已发现终局数；GUI 同样每 0.5 秒批量消费进度队列，但 Pygame 输入、hover、暂停/恢复和动画保持正常帧率；
- 节点级事件附带有界的增量预览批次：站位角色、最近发现或更新的节点、最近生成的边及派生标签；预览数据不写入状态签名和 interval；
- 站位开始事件先在结果表创建“计算中”占位行，节点事件实时更新该行的状态数、边数、终局数和耗时，完成事件原位替换为正式 wide/narrow 结果；
- DAG 面板在运行中固定显示一个活跃站位的滚动局部 DAG，完成后自动切换到下一活跃站位；窗口只保留根节点与最近节点，并过滤悬空边，防止跨进程消息和绘制成本随完整图无限增长；
- 实时节点首次进入可见子树时记录本地可见时间，绘制层在短时内对节点、连线和文字颜色做透明度插值；节点后续状态覆盖保留原首见时间；
- DAG 为每个站位维护本地展开节点集合。初始只布局入度为零的局部入口；点击节点在展开/收起状态间切换，可见图仅沿展开节点向下遍历。布局、hover 命中、边标签和节点绘制只处理该可见图；
- DAG 标题区提供“全部展开 / 全部收起”按钮：展开将当前观测图内所有有子边节点加入展开集，收起清空该集合；两个操作均只更改 UI 本地状态；
- 开始按钮旁提供暂停/恢复控件；暂停信号由 GUI 主进程控制并共享给 worker，搜索循环在下一节点展开前等待，恢复后沿原 frontier 继续；
- DAG 节点只绘制紧凑编号与阶段标记；搜索内存与 SQLite `state_json` 保存无损紧凑快照，实时预览批次和 hover 才按需重建只读 GameState 字典。hover 以多行检视器完整渲染所有 GameState 字段和每名玩家字段，不再限制为摘要的固定行数；
- interval 回传不再将子节点转换为 `RobustIntervals` 列表；直接从节点的四个浮点边界流式累加 count/sum/min/max，使单个高出度节点的额外空间为常数；
- 昼夜展开不再先构造节点的完整 `StateTransition` 列表；战术 profile 内的合法动作以生成器逐条交给 DAG 合并层，单条转移完成签名和边原因归并后即可释放临时 GameState。该变化只降低单节点瞬时内存，不跳过任何 profile、目标或票型；
- GUI 只配置一个 worker 时也通过 `ProcessPoolExecutor` 执行站位搜索；Pygame 主进程只保留绘制、事件合并与 SQLite 单写。子进程崩溃通过 future 错误返回 GUI，不让原生访问冲突终止界面进程；
- CLI 的站位批处理同样始终通过隔离子进程执行，即使只有一个站位且 `parallel_workers=1`；CLI 主进程不直接进入长时间状态展开，worker 原生异常由进程池边界转换为可报告的任务失败；CLI 未提供外部结果队列时，由批处理协调器创建生命周期受控的 Manager 有界队列，搜索结果禁止退化为整棵 DAG 的 Future 返回值；
- 站位 DAG 不作为单个 Future 返回值跨进程复制；有界结果队列按摘要、节点批次、边批次、完成标记依次传递，独立写线程持续落库，使搜索内存、IPC 队列和 SQLite 批次都有固定上限；
- 每个角色、运行选项、战术分组和战术复选框提供 hover 文本，解释分支语义与禁用条件；
- 计算在线程或子进程中运行，所有绘制只在 Pygame 主线程发生；
- GUI 固定 DFS；
- 智能投票默认勾选；
- 白天/黑夜战术采用可扩展分组与复选框组合；
- 智能投票关闭时折叠并禁用战术；
- 角色变化实时更新夜间战术可用性；
- 结果表分页；
- DAG 支持平移、缩放、节点选择和边原因详情；
- 玩家 icon 区分真实身份、声明、公共确认和私有查验；
- wide/narrow 同时显示，边颜色固定按 wide；
- UI 固定中文，不显示语言选择按钮。

### 2026-08-23 CLI 压力栈验证

- 5 人、1 狼、无神职、5 个唯一站位、2 worker：DFS 与 BFS 均退出 0，均得到 95 个状态、好人路径 600、狼人路径 3600，wide/narrow 结果完全一致；最终实现复跑耗时分别约 3.18 秒；
- 最终实现连续启动 10 次上述 DFS CLI：10/10 退出 0，共调度 50 个站位任务、950 个状态，累计约 33.57 秒，无 worker 异常和父进程异常；
